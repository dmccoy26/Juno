# Mission 15 — refine Juno’s native Mac interface

November 12, 2026. Baseline is installed preview.29 and source commit `201acb8`. This document is the implementation brief.

Make it easy to answer three questions as soon as Juno opens. What needs my attention? What has Juno prepared? What needs my review before I act? Retain the Mac Studio and MacBook Air workflow, local model, read-only source connections, manual meeting mode, and existing records and offline edits.

The preliminary audit used the installed app’s accessibility tree to inspect the main sidebar destinations, Settings routes, four Plan views, schedule display modes, and briefing and email review entry points. The dark Settings window was also inspected visually. The [control inventory](../reports/2026-11-12-preview29-control-inventory.md) records 558 declarations across the native app and worker portal. The inventory includes repeated declarations and wrappers. Conditional UI, native menu items, system prompts, physical laptop layouts and individual action outcomes still need execution evidence. The competitor review uses public vendor documentation.

## Apply the Mac conventions throughout

- Give the window a clear navigation hierarchy. Keep frequent actions next to the content they affect and provide equivalent menu commands for toolbar actions. Preserve search, selection and scroll position when moving between a list and an inspector. Verify the sidebar toggle and toolbar overflow at narrow widths. [Apple macOS design](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos) · [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) · [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- Use the system typography, semantic colors, SF Symbols and standard control styles. Create hierarchy with spacing, type weight and alignment. Give the main action a clear label and use an accessible name and tooltip for icon-only controls. Keep ordinary controls comfortably sized for Mac pointer use, using Apple’s 28-point default as the target and checking the 20-point minimum. Use text or symbols alongside color for state. [Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) · [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)
- Use an inspector for browsing details and a sheet for a focused edit or decision. Make Save, Apply, Cancel and Close distinct by behavior. Keep fields visibly labeled after entry and explain disabled actions with a short reason nearby. Place important controls where resizing or scrolling cannot hide them. [Apple Windows](https://developer.apple.com/design/human-interface-guidelines/windows) · [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) · [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- Give asynchronous work explicit states for preparing, ready, offline, retrying, blocked, and failed as applicable. Keep navigation responsive while sources or the model are working. Use quiet transitions, respect Reduce Motion, and check contrast and focus in both appearances. [Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) · [Motion](https://developer.apple.com/design/human-interface-guidelines/motion)

## Execution and completion

1. **Baseline.** Expand the inventory into a runtime ledger. For each control record its path, label, enabled conditions, keyboard and pointer entry, expected result, and evidence. Include dynamic rows, menu options, context menus, native window controls, OS prompts, and conditional host and laptop screens. Capture baseline layouts with representative synthetic data. Record the exact OS, build, viewport, appearance and input method.
2. **Daily work and reports.** Prototype the navigation, Today, the issue inspector, the daily check-in and the report review flow. Compare the number of actions and elapsed time against preview.29 for finding a draft, resuming a check-in, reviewing an issue and finding a room/person window. Use HumanLab scenarios and a native walkthrough to validate the result.
3. **Schedules, evidence and setup.** Apply the shared control patterns to the remaining surfaces. Test large task and resource lists, offline and reconnect, denied or delayed authorization, conflict recovery, and background preparation while switching views. Record any changes in source scope or data behavior as regressions.
4. **Release acceptance.** Exercise every inventory entry or record the exact dependency preventing a test. Cover mouse, keyboard-only, VoiceOver, light/dark, increased contrast, larger text, Reduce Motion, narrow MacBook window and wide desktop. Verify draft recovery and saved output after restart and on the paired laptop. Test a real automatic Friday generation using an isolated week with no prior drafts. Verify that LWR, VISU and Performing Arts drafts stay separate and that the Dean receives Holy Cross follow-ups as talking points. Use a disposable fixture for destructive operations and keep private data out of committed screenshots and logs.

Deliver the completed ledger, before-and-after captures, usability results, regression evidence and updated build status. Keep incomplete checks visible until someone runs them. Measure the daily workflows before claiming improvement.
